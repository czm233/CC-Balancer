# CC-Balancer · 额度规划实验室

通过双时钟模拟 Coding Plan 的 5 小时额度窗口，调整首次触发时间，查看工作时段的额度压力与预计空窗时间，生成交给 AI 编写定时调用脚本的 Prompt。

在线使用：[CC-Balancer](https://czm233.github.io/CC-Balancer/)

## 使用

1. 设置工作与午休时间。
2. 填写平常一份额度能支撑的工作时长；选择上午或下午更忙，会让该时段消耗翻倍、可支撑时长减半。
3. 拖动首次触发时间。内圈琥珀色表示工作、绿色表示午休，外圈两种蓝色交替表示连续 5H 周期。
4. 查看每个窗口的“有余量 / 刚好够用 / 偏紧”及预计空窗时间。首次触发旁显示保守暂停使用时段。
5. 生成并复制脚本 Prompt，让你的 AI 根据接口、时区及执行日期配置定时请求，内容固定为 `say OK`。

```mermaid
flowchart LR
  A[设置工作和消耗习惯] --> B[调整首次触发时间]
  B --> C[查看窗口状态与空窗时间]
  C --> D[复制脚本 Prompt]
  D --> E[由自己的 AI 配置定时调用]
```

设置仅保存在当前浏览器。本工具不连接账号、不发送 API 请求。按首次有效调用开启固定 5 小时窗口推算，不读取实际额度状态；真实服务规则可能不同。

## 计算约定

- 额度折算为用户设定的常规工作分钟数；更忙时段每工作一分钟消耗两分钟常规额度，午休不消耗。
- 窗口需求与一份额度比较，生成有余量、刚好够用或偏紧状态；平均压力取各工作窗口的压力指数算术平均，并不保证所有窗口都够用。
- 空窗时间按逐分钟未满足需求比例累加，只计算工作时间；不把积压工作移到下一窗口。显示时向上取整到分钟，总计对原始分钟数求和后取整。
- 有午休时以午休起止划分上午和下午，无午休时以 12:00 分界。当前面向同日白天工作，不包含夜班、周额度或多个账号。
- 提前五小时暂停使用是保守安排；真实请求成功不等于新窗口成功开启。
- Prompt 要求定时任务每个计划节点只请求一次，不检测窗口、不重试、不补跑、不自动调整计划。

## 本地开发

```bash
pnpm install --frozen-lockfile
pnpm dev
```

访问 http://127.0.0.1:10220/CC-Balancer/ 。纯前端，无需数据库、Docker 或密钥。

```bash
pnpm build
pnpm lint
node tests/planner.test.mjs
```
